## 1. 원칙: 허용의 기준은 "위험" (CLAUDE.md 불변 규칙)

- **파괴적이지 않으면 연다.** 1인·서버 없음 프로젝트에서 승인 창이 지켜 줄 "남의
  변경"이 없다. 사용자는 커밋·테스트·빌드·설치·조사에 관여하지 않는다 — 창이 뜨면 결함이다.
- **트레이드오프**: "승인한 것만 돌았다"는 보장 대신 git 이력·작업 로그가 그 역할을 한다.
- **남기는 것** (사람이 본다):
  - 파괴적 명령 — 삭제류·`git reset --hard`·`git push --force`·`git clean`·`git checkout --`.
    `settings.json` deny에 셸 도구별로 둘 다 있다. allow 와일드카드로 덮이지 않게 한다.
  - 패키지 **추가** = 잠금 파일에 없는 새 의존성(`pip install <새 패키지>`·`flutter pub add`·
    `npm install <패키지>`) — 공급망. 잠금 파일대로 **설치**하는 `pip install -r`·`pub get`·`npm ci`는
    추가가 아니라 연다(CLAUDE.md 불변 규칙).
  - 다운받은 실행물(스크립트·바이너리)의 실행 — 데이터 다운로드와 구분한다.
- **못 없애는 것**: `.claude/`·`.git/` 안의 Write/Edit는 규칙과 무관하게 항상 묻는다(보호
  디렉토리 `[H12]`). 프로젝트 밖 디렉토리 읽기는 세션당 한 번 묻는다 `[H8]`. 그냥 받는다.
- **승인 창이 반복되면 처방 순서**: ① 이미 열린 형태로 부르고 있나(습관 — 반복되면 훅)
  ② 규칙 추가. 한 세션 154회 반복의 원인은 규칙이 아니라 습관이었다 `[H1]`. `git add -A`가 열려
  있는데 `git add <경로>`로 불러 물은 것도 같은 범주다 `[H12]`.

## 2. 병목 측정법

- **★ 먼저 실측 기록을 본다** — 훅 `log_permission_request`(PermissionRequest)가 **승인 창이 실제로 뜬 호출만**
  `.claude/permission_requests.jsonl`에 적고, `measure_approvals.py`의 첫 절 `[실측]`이 센다. 서브에이전트 여부와
  Claude Code가 제안한 규칙(열면 안 묻게 되는 정답 후보)까지 남는다 `[H17]`. 아래 예측·벽시계는 그다음 보조다.
- `scripts/measure_wait.py` — tool_use↔tool_result 간격으로 **호출별 벽시계**. `--grep <명령>`으로
  같은 호출의 전후를 비교한다(절대값에는 명령 자체 시간이 섞인다 `[H2]`).
- `scripts/measure_approvals.py` — 원인 **분류**. 예측이며 양쪽으로 틀린 실사례가 있다 `[H2]` —
  어디를 볼지 고르는 데만 쓴다. 규칙 문법이 하네스와 이 분석기 두 곳에 있으므로 어긋나면
  보고서가 거짓말을 한다 — 대조 테스트가 있다 `[H10]`.
- 승인 대기는 상한이 없다(실행 12초가 벽시계 156초 `[H2]`).
- **"창이 떴는가" 판정법** — 한 가지로 단정하지 않는다:
  - **실측 기록에 그 호출이 있는가** — 가장 직접적이다. 기록 파일이 없거나 0건이면 "안 물었다"와 "훅이 안
    돌았다"를 못 가르니 아래로 내려간다 `[H17]`.
  - 벽시계만으로는 못 가른다(사용자가 2초 만에 누르면 정상 실행과 같다 `[H5]`).
  - `settings.local.json`에 **이번에 새로** 적혔는가 — "항상 허용"을 눌렀다면 반드시 적힌다.
    단 **"한 번만 허용"은 아무것도 안 남긴다** `[H12]`.
  - **사용자가 옆에 있으면 묻는 것이 가장 확실하다.**
- 호출이 0건으로 나오면 '깨끗함'이 아니라 실패다 — 트랜스크립트 형식·경로부터 본다.

## 3. 허용 규칙 작성법

1. **규칙을 추측하지 않는다.** 사용자가 "다시 묻지 않기"를 한 번 고르게 한다 — 매칭하는 그
   코드가 `settings.local.json`에 정확한 패턴을 적는다 `[H3]`.
2. **효력이 있는 것은 `settings.local.json`뿐이다.** `settings.json`의 `allow`는 이 환경에서
   안 걸린다(`hooks`·`env`·`deny`는 산다 — deny는 파괴적 명령을 던져야 시험되므로 확인하지
   않았고 지우지도 않는다) `[H6]`. local은 gitignore라 공유 불가 — 새 클론은 §5 스타터로
   시작한다. 그래서 템플릿 `settings.json`의 allow는 비어 있다.
3. **규칙 문법**:
   - 와일드카드는 작동한다. **패턴에 역슬래시가 있으면 죽는다** — 경로는 슬래시로 부르고
     슬래시로 등록한다 `[H6]`.
   - `X*`(공백 없이)는 `X`와 `X <인자>`를 함께 받는다 `[H10]`.
   - **`X:*`(콜론+별표)는 `X *`와 동등하다** — 공식 문법이고 패턴 끝에서만 와일드카드다(가운데 콜론은
     리터럴). 승인 창은 공백 형태를 적지만 손으로 쓴 규칙·다른 프로젝트에서 온 규칙은 이 형태가 흔하다.
     분석기가 이걸 몰라 거짓 보고서를 낸 실사례 `[H15]`. 출처: code.claude.com/docs/en/permissions.
   - `Bash(...)`와 `PowerShell(...)`은 별개다 — **양쪽에 넣는다** `[H1]`.
   - 한글(비ASCII)이 든 명령을 "다시 묻지 않기"로 열지 않는다 — 파일명이 깨져 적힌다
     `[H9]`. 열어야 하면 ASCII 경로로 부른다. (단 `git add *`처럼 와일드카드 규칙이 있으면
     한글 인자도 걸린다 `[H12]`.)
   - 자동 승인이 위험한 명령은 인자를 필수로 건다(`dart format *` — 맨몸 전체 포맷은 묻는다).
   - `deny`가 `allow`보다 우선한다. deny도 셸 도구별로.
4. **일회성 명령을 열지 않는다** — 다시 부를 일이 없어 이득 0, 권한만 남는다 `[H9]` `[H11]`.
   세션 UUID·스크래치패드 절대경로·인라인 파이썬이 박힌 규칙이 전형이다. 호출 형태로 푼다(§4).
5. **규칙이 걸리는지 검증할 때 읽기 전용 명령을 쓰지 않는다.** `git status`·`git log`류는
   규칙과 무관하게 자동 허용처럼 동작해 어떤 규칙을 넣어도 "걸렸다"가 나온다 `[H5]`.
   **실제로 묻던 명령으로 검증한다.** ⚠️ 단 "자동 허용 부류"를 단정하지 말 것 — 자동 허용으로
   보였던 `Set-Location`이 다른 환경·시점에선 9건을 물었다 `[H14]`. **물면 규칙을 넣는다.**
6. **규칙은 즉시 걸린다 — 재시작을 기다리지 않는다** `[H14]` (local에 넣자마자 같은 세션의
   다음 보고서에서 사라짐). **안 걸린 것처럼 보이면** ① 죽은 settings.json에 넣었는지 ② 벽시계로
   판정했는지부터 본다 `[H4]` `[H5]`. 그 자리에서 실제로 묻던 명령으로 재검증하고, 판정은 §2 판정법.
7. **audit 때 local을 청소한다 — 넓히는 게 아니라 줄이는 작업이다** `[H14]`. 지난 세션의
   스크래치패드 경로, 다른 저장소 경로, 깨진 한글, 훅이 막는 형태의 규칙은 죽은 규칙이다
   (실사례: 169개 → 64개).
8. **규칙을 닫을 때는 두 파일을 함께 본다** — local에 같은 규칙이 있으면 그쪽이 계속 연다 `[H6]`.

## 4. 호출 형태 — 한 호출 = 한 명령, 앞에 무엇도 붙이지 않는다

**긴 명령이 곧 긴 승인 대기다** — 사람이 읽고 판단하는 시간이라 규칙으로 못 줄인다(실측:
`git add -A` 38초 vs 경로가 박힌 `curl` 83초).
명령을 짧게 만드는 것이 규칙을 늘리는 것보다 효과가 크다.

| 피할 형태 | 왜 | 대신 |
|---|---|---|
| `cd X && cmd` / `Set-Location X; cmd` (훅 `no_redundant_cd`가 `cd` 복합을 막는다) | 접두사 규칙에 안 걸리거나(Bash), 앞머리 하나로 뒤까지 통째로 통과해 승인 이력을 못 믿게 된다(PowerShell) `[H1]` `[H7]`. `cd`가 허용돼 있어도 뒤 명령의 경로가 `../../..`로 바뀌어 안 걸린다 `[H16]` | 루트에서 경로를 인자로. 정말 옮겨 가야 하면 `cd` 단독 호출. cwd는 호출 사이에 유지된다 |
| `FOO=bar cmd` / `$p = "…"; cmd` | 리터럴로 시작하지 않아 allow 규칙에 안 걸린다 `[H1]`. 공식 문서: **알려진 안전 변수**(`NODE_ENV` 등) 대입만 매칭 전에 벗겨지고 그 외 변수는 안 걸린다(deny는 어떤 대입도 넘어 매칭) `[H15]` | `settings.json`의 `env` |
| `& (Join-Path …)` 식 표현식 시작 | 같은 이유(77.8초) `[H6]` | 전체 경로를 글자 그대로, 그 리터럴로 규칙 등록 |
| `& "<경로>"` (호출 연산자+따옴표) | 규칙은 맨몸을 전제 — 같은 adb devices가 27.6초 vs 2.2초 `[H14]` | 경로에 공백이 없으면 `&` 없이 맨몸으로 |
| `git -C <저장소 루트>` — 읽기·쓰기 모두 (훅 `no_redundant_cd`가 막는다) | 규칙이 `git add *` 형태를 전제(21건 147초) `[H6]` `[H14]`. 읽는 `-C`도 표기마다 규칙이 따로 필요해 새 표기로 빠져나갔다(19,833초 1건) `[H16]` | 루트에서 맨몸으로. 드리프트 확인은 맨몸 `git status`. 다른 저장소를 가리키는 `-C`는 막지 않는다 |
| `cat > / cat >>` heredoc · `sed -i` (훅 `no_shell_file_write`가 막는다) | 셸 쓰기는 허용 규칙이 없어 매번 묻는다 — 131건 중 126건이 서브에이전트 `[H16]` | `Write`/`Edit` 도구(작업 폴더 안이면 auto·acceptEdits 모두 안 묻는다). `sed`는 acceptEdits가 자동 허용하는 목록에 있어 "매번"은 `cat >`에만 맞다 `[H18]` |
| `A; if ($?) { B }` 복합문 | 어느 규칙에도 안 걸린다(4건) `[H14]`. 앞머리 하나로 통째로 통과한 관측도 있다 `[H7]` — 어느 쪽이든 처방 동일 | 두 번에 나눠 부른다 |
| 공백 없는 경로를 따옴표로 | `git commit -F "경로"`가 `-F *`에 안 걸림(18.5초) `[H6]` | 따옴표 없이 |
| `cmd \| Select-String` / `2>&1` | PowerShell에선 꼬리가 검사되지 않고, 자르려다 3~7배 `[H7]` `[H8]` | 그냥 받는다 — 큰 출력은 하네스가 파일로 떨궈 준다 |
| `python -c "…"` | 이스케이프째 박제되는 죽은 규칙 `[H11]` | 스크립트 파일 |
| 스크래치패드 절대경로 (훅 `no_scratchpad_path`가 막는다) | 세션 UUID가 박혀 다음 세션에 안 걸린다 `[H11]` | 파일은 Read/Write 도구로, 스크립트는 `scripts/`에 두고 경로는 스크립트 안에서 계산 |
| 셸에서 환경변수 확인 | 일회성(82.3초) `[H11]` | 스크립트 안에서 `os.environ` |
| 셸 `for/do/done` | 규칙에 안 걸린다 | 파이썬 |

- **★ 앞머리 통과를 우회 수단으로 쓰지 않는다.** 허용된 명령을 앞에 붙여 뒤엣것을 통과시키면
  사용자는 자기가 승인한 것만 돌았다고 오해한다. 명령은 있는 그대로 부르고, 물으면 물리는
  대로 둔다. 속도보다 이쪽이 우선이다 `[H7]`.
- **작업 디렉토리**: 트리 안 `cd`는 유지되고, 트리 밖은 거부·루트로 리셋된다 `[H5]`. 유지되기
  때문에 **드리프트** 위험이 있다 — 하위에서 루트용 명령을 부르면 에러 없이 조용히 다른 일을
  한다(`pytest tests/` 0건 통과, `git add -A` 하위만). 하위에 들어갔으면 끝나자마자 돌아온다.
  100% 믿지도 않는다 — 중간에 초기화된 실측이 있다. "찾을 수 없다"류로 죽으면 cwd부터 본다.
  **Bash·PowerShell 도구는 cwd를 공유하고, 승인된 추가 디렉토리로의 `cd`는 트리 밖이어도
  유지된다** `[H13]` — 다른 저장소에서 작업한 뒤 `git add -A`를 부르면 그쪽이 담긴다.
  다른 저장소에 들어갔으면 **돌아오기 전에 `git status`로 어느 저장소인지 본다.**
- **여러 줄 커밋 메시지**: here-string·인라인으로 넘기지 않는다(`pathspec` 오류). 저장소 루트
  `.commit_msg.txt`(gitignore)에 쓰고 `git commit -F .commit_msg.txt`. 경로를 고정해야 규칙
  한 줄로 영구히 끝난다. `.git/` 안에 두지 않는다(보호 디렉토리, 137초) `[H8]`.

## 5. settings.local.json 스타터

Flutter·Windows 프로젝트에서 실제로 쓰던 것 기준이다. 초기화 때 `.claude/settings.local.json`에
붙여 넣고(없으면 만든다), **이 스택에 없는 줄은 뺀다.** 전역 `python` 기준 — 가상환경이면
`.venv/Scripts/python.exe`처럼 슬래시 경로로 바꾼다. `additionalDirectories`의 프로젝트 폴더명은
`~/.claude/projects/` 아래 실제 이름으로(경로의 `:`·`\`가 `-`로 바뀐 형태).

```json
{
  "permissions": {
    "allow": [
      "WebSearch",
      "WebFetch",
      "Write(.commit_msg.txt)",
      "Edit(.commit_msg.txt)",
      "PowerShell(git add *)",
      "PowerShell(git commit -F .commit_msg.txt*)",
      "PowerShell(Set-Location *)",
      "Bash(git add *)",
      "Bash(git commit -F .commit_msg.txt*)",
      "Bash(cd *)",
      "PowerShell(flutter test)",
      "PowerShell(flutter test --reporter failures-only)",
      "PowerShell(flutter analyze)",
      "PowerShell(flutter doctor)",
      "PowerShell(flutter devices)",
      "PowerShell(flutter pub get)",
      "PowerShell(flutter pub outdated)",
      "PowerShell(flutter clean)",
      "PowerShell(flutter build apk*)",
      "PowerShell(dart analyze)",
      "PowerShell(dart format *)",
      "PowerShell(python -m pytest *)",

    ],

      "C:/Users/user/.claude/projects/C--Users-user-Documents-<프로젝트폴더명>"
    ]
  }

```

- **이 스택의 자리 넷을 채운다** — Flutter 줄을 지우고 나면 git·python 몇 줄만 남는다. 아래 네
  자리가 루틴 작업(커밋·테스트·빌드·설치)의 전부다. **명령을 추측해 적지 말고**, 실제로 물었을 때
  "다시 묻지 않기"로 받은 정답 패턴을 넣는다(§2 판정법). Bash·PowerShell 양쪽 다.
  - **테스트** — 위 블록의 `flutter test` / `--reporter failures-only` 자리
  - **빌드** — `flutter build apk*` 자리
  - **정적 분석**(타입체크·린트·포맷) — `flutter analyze` / `dart format *` 자리
  - **잠금 파일대로 설치** — `flutter pub get` 자리. 패키지 **추가**는 열지 않는다(§1)
- `flutter test *`는 안 연다 — 개별 실행은 훅이 막고, 맨몸과 failures-only면 충분하다.
- `Set-Location`/`cd` 규칙을 넣는 이유: cd 훅이 권장하는 대체 수단인데 자동 허용이 아닌
  환경에서 매번 물었다(9건 실측 `[H14]`). 단독 cd는 파괴적이지 않다.
- `flutter pub *`가 아니라 `get`·`outdated`만 — `pub add`는 패키지 추가(§1 남기는 것).
- `Edit(.claude/**)`류는 넣지 않는다 — 죽은 규칙이다 `[H12]`.
- ⚠️ `additionalDirectories`는 문법만 적었고 **실측 전**이다 — 다음 `/approval-audit`에서
  디렉토리 승인이 뜨는지로 판정한다. **대안 실측 1건** `[H15]`: 스크래치패드 읽기는
  `additionalDirectories` 없이도 allow에 `"Read(//c/Users/user/AppData/Local/Temp/**)"` 한 줄로 안 물었다
  (Windows·Git Bash). 경로는 환경에 맞게 — `//c/`는 Git Bash가 쓰는 드라이브 표기다.
- **auto 모드에서는 넓은 허용 규칙이 꺼진다**(공식 문서): `Bash(*)`·`PowerShell(*)`, `Bash(python*)` 같은 인터프리터
  와일드카드, 패키지 매니저 run, Agent·Monitor 규칙. 좁은 규칙(`Bash(npm test)`)은 남는다. 위 스타터의
  `python scripts/*`류가 여기에 드는지는 문서에 없고 **미확인**이다 — `[실측]` 절에 그 명령이 새로 뜨는지로
  판정한다(추측으로 스타터를 고치지 않는다) `[H18]`.
- 붙여 넣은 뒤 실제로 묻던 명령으로 확인한다(§2 판정법).

## 6. 훅 — 문서로 안 막히면 구조로

문서에 두 곳 적힌 함정이 한 세션에서 154회 반복됐다 `[H1]`. 반복되는 호출 습관은 PreToolUse
훅으로 막는다. **최대 6종**이 동봉·등록돼 있다(`settings.json`의 hooks, matcher `Bash|PowerShell`
한 블록). 아래 표의 선택형은 초기화 때 빠지므로 **개수가 아니라 실제 파일을 본다**:

| 훅 | 막는 것 |
|---|---|
| `no_redundant_cd` | `cd <저장소 루트> &&\|; …` 접두사 |
| `no_output_filter` | `2>&1`·`\| Select-String/Select-Object` 출력 자르기 `[H8]` |
| `no_targeted_flutter_test` | `flutter test <인자>` — 전체(23~27초)가 파일 하나(158~206초)보다 싸다. Flutter 없으면 세 곳(훅 파일·settings.json 항목·`tests/test_no_targeted_flutter_test.py`)에서 삭제 — CLAUDE.md 초기화 5번 |
| `no_inline_python` | `python -c "…"` `[H11]` |
| `no_scratchpad_path` | 세션 UUID가 든 스크래치패드 절대경로 — 다음 세션에 규칙이 안 걸린다 `[H11]` |
| `no_shell_file_write` | `cat >`·`cat >>` heredoc·`sed -i` 같은 셸 파일 쓰기 — `Write`/`Edit`로 `[H16]` |

규범 (전부 실측에서 나온 것):
- **양쪽 셸에 건다.** 한쪽에만 걸면 반대쪽으로 그대로 통과한다 `[H11]`.
- **등록 직후 ① 막히는 명령 ② 정상 명령을 둘 다, Bash·PowerShell 양쪽에서 실제로 부른다.**
  통과하는 쪽만 보면 죽은 훅과 정상 훅의 증상이 완전히 같다 `[H11]`.
- 훅은 재시작 없이 즉시 적용된다 `[H11]`.
- deny 출력은 반드시 `hook_io.deny()`로 낸다. `json.dumps(..., ensure_ascii=False)`를 직접 쓰면
  cp949 콘솔에서 죽어 훅이 통째로 무력화된다 `[H11]`. 훅 회귀 테스트는 `PYTHONIOENCODING`을
  cp949로 고정해 돌린다(`tests/test_hook_io.py`) — 현재 환경을 물려받으면 아무것도 검증하지 않는다.
- 훅 경로: 템플릿은 `$CLAUDE_PROJECT_DIR`로 두었다. **환경에 따라 다르다** — 빈 값인 환경이 있었고
  `[H11]`, 데스크톱 앱에서는 채워져 있었다 `[H15]`. 단정하지 말고 **등록 직후 막히는
  명령을 불러 확인**하고, 안 막히면 절대 경로(슬래시)로 바꾼다.
- **훅 테스트에서 자식 파이썬의 인코딩을 물려받지 않는다.** PowerShell 도구 환경에는
  `PYTHONIOENCODING=utf-8`이 있고 Bash 도구 환경에는 없다 — 같은 테스트가 셸에 따라 갈린다
  `[H13]`. 인코딩을 검증하는 테스트는 cp949로 고정, 그 외는 utf-8로 고정한다.
- **차단 훅을 더 두면 `tests/test_hook_io.py`의 `CASES`에도 넣는다** — 빠지면 그 훅만 cp949·한글 입력 검증에서
  빠진다 `[H17]`. 훅 입력은 `hook_io.read_input()`으로 읽는다(`json.load(sys.stdin)`은 cp949로 읽어 한글이 든 명령에서 판정이 갈린다).
- 반례를 테스트에 넣는다(맨몸·정상 호출까지 막으면 고칠 방법이 없다). 재보지 않은 것을 막지
  않는다(YAGNI). 훅이 고장 나면 막지 않고 통과시킨다.
- 그 형태가 정말 필요하면 사용자에게 말하고 승인을 받는다. **훅을 우회하지 않는다.**
- **예외는 "문자열이 고정인가"로 연다.** `flutter test --reporter failures-only` 한 형태만 훅
  예외 + 정확 일치 규칙. 가변으로 열면 다시 매번 달라진다. 연 예외의 반례를 테스트에 넣는다.
- **효과 검증은 "호출 형태가 바뀌었나"로 본다** `[H8]` — "작업이 쉬웠나"가 아니다.
