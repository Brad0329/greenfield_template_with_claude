# 이력: 승인 대기 실측 (템플릿 원본 전용)

> **독자: 템플릿 원본을 고치는 AI.** `노하우_승인_대기_최소화.md`의 결론이 "왜 그런가", "뒤집어도 되는가"를
> 따질 때만 연다. 그 파일의 `[H#]`가 여기 항목이고, 여기의 `§N`은 그 파일의 절 번호다.
> **새 프로젝트로 가져가지 않는다 — CLAUDE.md 초기화 6번에서 지운다.** 남의 프로젝트 수치이고 뒤집힌 결론이
> 섞여 있어 현재 지시로 오독할 위험이 있다. **지켜야 할 결론은 노하우 파일에 둔다 — 여기에만 있는 현재형 지시는
> 새 프로젝트에서 사라진다**(분리 당시 [H17]·[H18]에 2건이 그렇게 남아 있어 노하우 §5·§6으로 옮겼다).
> 승인 대기 밖의 노하우(검증·설계·프로세스·작업 트랙)가 바뀐 경위는 `이력_노하우_결정기록.md`에 있다.
> 날짜순이다. 결론이 뒤집힌 것도 지우지 않는다. 각 항목: 무엇을 봤고 → 무엇을 결론냈고 → (뒤집혔으면) 왜.
> 절을 추가·개명하면 아래 목차도 고친다 — `tests/test_playbook_toc.py`가 대조한다.

## [H7] hanjadic 2026-08-20 — 파이프·복합의 실제 검사 방식 (PowerShell 도구)
앞머리를 `git log`로 고정하고 꼬리만 바꿈:

| | 명령 | 결과 |
|---|---|---|
| T1 | `git log \| Select-String …` | 안 물음 |
| T2 | `git log \| Out-File <경로>` | **안 물음** (파일을 쓰는 cmdlet인데도) |
| T3 | `git log --oneline -1; Copy-Item …` | **안 물음** |
| T4 | `Copy-Item …` (혼자) | **물음** |

- T3·T4가 갈린다 → PowerShell 도구에서는 앞머리가 줄 전체를 결정하고 `|`·`;` 뒤는 검사되지
  않는다. 파이프 꼬리용 규칙은 넣어도 효과가 없다("관측되지 않는 값").
- 종전 서술 "복합 명령은 접두사 규칙을 못 통과해 매번 묻는다"가 정정됨 — 피하는 규칙은 유지,
  이유가 "안 걸려서"에서 "통째로 걸려 버려서"로 바뀜.
- 같은 날 Bash 도구의 `;` 복합은 앞머리가 규칙에 없자 그대로 물었다 — 도구 간 일반화 금지.
- hanmunstudy 2026-08-22 재확인: `git status --short; git log --oneline -1` 안 물음(T3과 일치).
